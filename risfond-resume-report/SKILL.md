# 锐仕方达猎头简历报告制作规范

## 触发条件（必须加载本skill）

当用户要求生成简历报告时，**必须首先加载本skill**，不得跳过：
- 用户说"生成报告"、"写简历报告"、"出报告"
- 用户提供候选人资料并要求生成 docx
- 用户说"用skill生成"（明确提示应使用 skill）
- 任何涉及候选人简历报告生成的请求

**⚠️ 绝对不要**：不加载 skill 直接生成报告。本 skill 包含 mandatory 确认步骤和格式规范，跳过会导致流程错误。

---

## ⓿ 速查铁律（每次开工前必读，10 条）

1. **流程**：分析 → 输出【核心优势】草稿 → 用户确认 → 输出【综合评估】全文预览 → 用户确认 → 生成 docx → 自动打开。**两步确认都不能跳**
2. **格式有问题先反编译**：手上有近期真实样本时，先跑 `scripts/docx_reverse_engineer.py <样本.docx>` 逐属性对标，**禁止凭肉眼看图猜属性**
3. **顾问名可配置**：优先级 = 用户本次指定 → 环境变量 `RISFOND_ADVISOR` → 模板默认值。用户没提就先问一句，**不要默认写死**
4. **【】标签一律不加粗**，且与内容**同一段**（如 `【职业状态】在职，1个月内到岗。`），不是标签单独一行
5. **标签格式**：`公司介绍：`/`工作职责：`/`看机会原因：`/`项目介绍：` 等 → 标签加粗、内容不加粗、同段
6. **编号职责逐项分段**：`工作职责：` 与第 1 项同段，后续 `2、3、4` **每项各占一段**
7. **工作年限精确到月**：`17年6个月`，禁止 `约17.5年`/`17.5年`
8. **学历是否统招要看时间线**：大专毕业后再读本科 = 非统招，**非统招不写进核心优势**，只在教育背景体现
9. **年营收/产值/产能是平台指标，不能跨公司合计**；销售额/降本额等个人业绩可以合计
10. **公司介绍必须 50-100 字**，搜索为空或不相关时基于简历原文提炼，**不可省略**

## 一、整体排版结构

### 0. 页眉页脚与顶部标题

**⚠️ 页眉 logo 必须在真正的 Word 页眉里，不是正文第一段的图片**（2026-11-04 连续 3 版返工的教训：当正文图片插入 + 按 15cm 插，导致 logo 跑进正文且大 2.5 倍）。

**页眉**：
- 图片 `assets/header_logo.png`（RISFOND logo，原图 633×88）
- 插入尺寸 **6.00 × 0.83 cm**，`section.header.paragraphs[0]`，`WD_ALIGN_PARAGRAPH.LEFT`
- ⚠️ 左对齐图带透明边距**视觉上会显得居中/偏右**，别被眼睛骗，以 XML `<w:jc w:val="left"/>` 为准

**页脚**（3 行，8pt，行距 1.0，段前段后 0pt，默认黑色）：
```
公司：锐仕方达人才科技集团有限公司常州第一分公司
地址：常州市武进区湖塘镇吾悦广场1幢12B03-12B05号
公司电话：15295000586
```
⚠️ python-docx 的 `footer.add_paragraph()` 会留一个空首段，需删掉，否则 footer[0] 是空行。

**顶部标题图**：`assets/title_report.png`，正文第一行居中，宽 15cm，段前 6pt 段后 12pt。

**模块标题图**：`title_basic_info/education/work_experience/project_experience.png`，插入 **8.00 × 0.66 cm**（❌ 不是 14.6cm，旧版错误会溢出版面）。⚠️ 若样本把图压扁插入（宽高比≠原图），必须同时传 `width` 和 `height`。

**图片红线**：不要企业 logo（页眉已有）、不要装饰性分隔线/页眉横幅（如 1180×64）。标题图**替代**【】文字标题的位置，不是额外添加。

### 1. 标题信息（正文区，顶部标题之后）
```
推荐职位：XXX	推荐顾问：<顾问名>
推荐日期：YYYY-MM-DD
```
- 推荐职位行可选——用户未提供目标职位可省略
- **顾问名（ADVISOR）是配置项**：① 用户本次指定 → ② 环境变量 `RISFOND_ADVISOR` → ③ 模板默认值。用户没提就先问"这份报告推荐顾问写谁？"

### 2. 候选人基本信息卡片（4行×2列无边框表格）

| 姓名：XXX | 性别：男/女 |
|---|---|
| 年龄：XX岁 | 学历：本科/硕士/大专 |
| 籍贯：省份-城市 | 婚姻：已婚/已婚已育/未婚 |
| 现居：省份-城市 | （留空） |

- ⚠️ **没有"到岗周期"行**——并入【职业状态】
- 无边框、无底色、宋体五号不加粗；用户没提供的字段留空

### 3. 综合评估（核心卖点区）

固定顺序，【】标签不加粗、与内容同段：
- **【职业经历】** 时间倒序，`YYYY/MM-YYYY/MM (X年X个月) 公司 职位`，时长**紧跟时间**
- **【核心优势】** 见「三、核心优势写作要点」
- **【职业状态】** 在职/离职 + 到岗周期，合并一句；离职/看机会可补原因
- **【家庭情况】** 婚姻、家庭位置、通勤
- **【薪资结构】** 目前薪资 + 期望薪资
- **【意向度】** 高/中/低
- **【面试安排】** 提前沟通（可选）

### 4. 教育背景
- 标题用图片，无则【教育背景】文字（不加粗）
- 五号 10.5pt，行距 1.5 倍，**无段前距、无开头空格**
- 每行一段：`YYYY/MM-YYYY/MM  学校  专业  学历(统招/非统招)`，多学历时间倒序

### 5. 工作经历（每段）
- 标题用图片，无则【工作经历】文字（不加粗）
- 标题行（**加粗 #2E75B5**）：`YYYY/MM-YYYY/MM(X年X个月)\t公司\t职位`
- `公司介绍：`（标签加粗，内容不加粗）50-100 字，含成立时间/总部或上市/主营/核心产品客户/规模
- `Base地点：`（可选）、`汇报对象：`（加粗 #000000）、`下属人数：`（加粗 #000000，0 人也写"0"）
- `工作职责：`（加粗）+ 编号；`工作业绩：`（加粗，如有）+ 编号
- **同公司多段经历**：时间连续→合并一条，职位栏"职位A/职位B"；时间非连续→分列两条，第二段可省公司介绍。【职业经历】列表与正文口径必须一致
- **同公司多岗位正文展开**（按时间倒序）：阶段标题行（加粗 #2E75B5）`YYYY/MM-YYYY/MM\t岗位名`，下设汇报对象/下属人数/工作职责，阶段间空行，全部阶段结束后写"看机会原因/离职原因"
- **离职原因 vs 看机会原因**：所有经历已结束→"离职原因"；最近一段标"至今"→"看机会原因"。**只有最近一段写，之前的不写**

### 6. 项目经历（销售/项目型岗位默认需要）
位于工作经历之后、尾部声明之前。
- 标题用图片，无则【项目经历】文字（不加粗）
- 标题行（**加粗 #2E75B5**）：`YYYY/MM-YYYY/MM\t项目名称\t项目角色`
- `项目介绍：`/`项目职责：`/`项目业绩：` 标签加粗内容不加粗；**业绩必须量化**
- 时间倒序，可与工作经历重叠；销售岗可列 5-10 个，技术/工程岗 2-4 个
- 保密需要时项目名写"国内某知名XX公司XX项目"
- 三段尽量齐全，确实无业绩数据可省"项目业绩"，但不能三段全省
- **纯技术岗简历无项目信息时可省略整个板块**

### 7. 尾部声明
```
以上是我公司对候选人XXX的调研分析报告，文件中有需要保密的内容，请传阅时严格控制在与此次招聘有关的负责人手中。此文件的内容是我公司与候选人之间的面试总结。请贵公司根据人才情况和公司实际情况给予其相应待遇。
调研单位：锐仕方达人才科技集团有限公司常州第一分公司
```

## 二、表达习惯

- 第三人称"人选"，正式客观
- 时间格式 `YYYY/MM-YYYY/MM (X年X个月)`，在职标"至今"
- 动词开头：负责、主导、建立、优化、提升、统筹、完善、推行、搭建
- 数据量化：管理X人、销售额X万、成本降低X%
- **薪资格式**：`XXk*X薪=XXw税前  综合年薪：XXw税前`
  - 非标准结构按实际写：`base 18k*12+半年度绩效（64开）=36w税前`、`固定月薪25k+季度绩效（平均3个月）=38w税前`
  - 综合年薪仍以"=XXw税前"结尾
- **工作年限精确到月**，从入职月算到离职月/至今，不用"约"，不用小数
- **只写客观事实，禁止主观推测**：不写"获客户充分信任""客户指定本人对接"等无事实支撑的评价

### 离职原因中性化表述指南

候选人原始离职原因含负面信息时，**弱化个人失误、归因于公司层面调整或客观因素**：

| 原始原因 | 中性化表述 |
|---|---|
| KPI太重/业绩压力大 | 公司近期调整了销售团队的考核体系与业绩目标设定，人选综合评估后决定寻求与自身资源和能力更匹配的平台发展 |
| 丢了大单/业绩不达标 | 公司近期进行组织架构优化与业务线调整，部分销售团队发生变动，人选希望寻求更稳定的发展平台 |
| 被裁员/部门解散 | 公司进行组织架构优化与业务线调整，人选希望寻找更能发挥自身资源优势的机会 |
| 与直属领导不和 | 公司高层人员变动较大，影响工作开展，人选希望寻求管理风格更匹配的平台 |
| 工资低/涨薪慢 | 人选在该公司已服务X年，近期公司战略方向发生调整，人选希望寻找更能发挥自身优势的机会 |
| 加班太多/强度大 | 公司近期业务节奏发生调整，人选希望寻求工作强度与生活质量更平衡的平台 |

推荐结构三选一：**归因公司调整**（最常用）/ **归因组织架构变动** / **强调主动选择**。
用户主动要求优化时，先展示原始原因 + 2-3 个中性化版本，选定后再写入。

## 三、核心优势写作要点

### 标准写法（4 条结构）

每条是一个完整自然段落，数字编号，不加粗：

1. **学历背景**（只写学校+专业，不写年限）
   - `人选本科/硕士毕业于XX大学（985/211/QS排名）XX专业`
   - ⚠️ 只写学校+专业；**非统本/专科不写学历**
2. **工作年限 + 行业经验 + 核心专业能力**（最重要，内容最丰富）
   - 设计/电气制图类能力置于编程之前（EPLAN → AutoCAD → PLC → HMI → 调试）
3. **技术工具/体系认证/专业技能** — 具体列出工具、体系、标准、方法论
4. **语言能力/团队管理/其他突出优势**（可选，信息密度高才写）

### 写作要点
- 语言精炼，每条 1 个完整段落，不拆小标题
- 量化数据：X年经验、X万销售额、X人团队、X%提升
- 突出目标岗位所在行业的专业术语
- 逻辑递进：学历→经验→技能→附加优势
- **推荐 3-4 条**；用户反复要求精简时，优先合并"管理体系类"与"无事故/改造类"
- 只能从实际工作经历提取，不添加无关信息；用户没提供年龄字段时基本信息中省略

### 学历表达规则
- ✅ 统招本科/硕士 → 写进核心优势第 1 条
- ❌ 非统招/专科 → 不写进核心优势，只在教育背景体现
- **判断方法看时间线**：大专毕业后再读本科（如大专 2008 毕业、本科 2010 入学）= 专升本非统招；本科与大专时间连续可能是统招专升本，需确认；只有一段本科且无大专通常是统招。**简历写"本科"不代表统招**

### 高信息密度版（用户偏好）
- **0-1 经验是核心亮点**：必须突出"从0-1工厂建设"
- **产值/规模数据前置**；**语言直接**："18年加氢工艺生产管理经验"而非"人选拥有18年化工行业经验"
- **不提证书**，聚焦实战经验；**项目成果前置**，用项目名称+规模证明能力
- ⚠️ **年营收/产值/产能是平台指标，不能跨公司合计**，应在每段公司介绍中分别标注；销售额/签约额/降本额等个人业绩可以合计

### 跨品类推荐：去产品、留共性
候选人经历跨品类时，核心优势**去掉具体产品名、保留可迁移的共性能力**，避免客户误判为"只做过某一种产品"。

### 语言能力分三档（不虚高）
精通（可作工作语言）/ 熟练（日常沟通无障碍）/ 一般（读写为主）。按候选人实际自评定档，不拔高。

### 销售类岗位核心优势模板（B2B大客户销售）
重点不在工具证书，而在**业绩数据、客户层级、解决方案能力、生态资源**：
1. 学历（统招才写）
2. X年XX行业B2B大客户销售经验 + 细分领域 + 擅长对接的决策层级别（CIO/CXO/厂长/副总/董事长）+ 解决方案类型
3. **业绩量化数据前置**：年度销售额/累计项目金额 + 标杆项目（项目名+金额+关键产品）+ 客户类型
   - 业绩横跨多家公司时用「相关业绩」子结构：`3.1 公司A-…；3.2 公司B-…；累计…，客户覆盖…`
   - 跨公司业绩必须明确标注归属，不得混淆
4. 生态资源（原厂合作关系）+ 渠道管理 + 团队管理 + 语言
- 决策层对接要写具体级别，不能只写"高层"
- 不提 CET/计算机二级等基础证书
- **三段式结构**（业绩横跨多家、用户要求主文精简时）：精简主文 2-4 条 + 「销售业绩与产品（按公司历程）：」+ 「核心客户资源：」，两个标签行均在【核心优势】板块内，不另起新板块

## 四、排版与字体格式规范

- **中文**：宋体（必须 `run.element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')`，否则渲染成 MS 明朝）
- **西文/数字**：Times New Roman（`font.name`），不要设成宋体
- **全文字号**：五号 10.5pt；**行距 1.5 倍**；段前段后 0pt
- **页边距**：上下 2.54cm，左右 3.17cm；页眉页脚距边 1.0cm
- **颜色**：工作经历/项目经历标题行 = Bold + `#2E75B5`（全文仅标题行用彩色）；`汇报对象：`/`下属人数：` = Bold + #000000；其余标签 Bold 黑色、内容不加粗黑色
- ⚠️ **每个 run 必须显式设置 `font.color.rgb`**，否则渲染偏浅
- 工作经历标题行三段用 `\t` 分隔；每段工作经历/项目之间空行
- 基本信息卡片每个字段独占一行，字段间不空行；教育背景无段前距、无开头空格

**加粗必须用 R() 函数参数控制**，禁止 `add_p('**标签：**内容')`——python-docx 不做 markdown 解析，星号会原样输出。

## 五、文件命名与交付

- 文件名：`锐仕方达-人选名字-职位.docx`；职位名含 `/` 时去掉（正文可保留）
- 生成后用 `Invoke-Item`（Windows）/ `open`（macOS）/ `xdg-open`（Linux）自动打开
- **生成后必须验证内容完整性**：用 python-docx 读回并打印所有段落文本，确认【教育背景】【工作经历】等确实写入
  ```python
  from docx import Document
  doc = Document(r'文件路径.docx')
  for i, p in enumerate(doc.paragraphs):
      if p.text.strip():
          print(f'[{i}] {p.text[:60]}')
  ```

## 六、工作流程

### 流程（默认模式）
1. **分析**：通读候选人资料，规划报告结构
2. **输出【核心优势】草稿**：对话框展示给用户确认，**必须等待确认，绝对不能跳过**
   - 草稿只输出核心优势文本，不含工作经历/薪资等
   - 用户通常迭代 2-4 轮（调整顺序、措辞、增删条目）
   - **JD 定向对齐**：用户提供目标岗位 JD 时，可据此调整核心优势排序与措辞，使第 2/3 条贴近 JD 关键词；调整前先给草稿
3. **输出【综合评估】全文预览**：核心优势确认后、生成 docx 前，先输出完整综合评估板块文字（职业经历→核心优势→职业状态→家庭情况→薪资结构→意向度），用户确认 OK 后再生成
4. **撰写生成**：由主模型直接生成脚本产出（平台支持子代理时可委托另一个模型，要点见 `references/subagent-prompt-template.md`）
5. **验证与交付**：检查内容完整性，自动打开文件

### 批量生成模式
一次提供多个候选人资料时：一次性分析全部，分别输出每人的核心优势草稿（合并到一条消息）→ 用户确认 → 一个 Python 脚本批量生成（函数封装每人逻辑）→ 一次性打开所有文件。公司介绍搜索并行执行。

### 用户补充信息处理
用户常在提供资料时附带简短笔记（如"前期商业调查 收购 商业谈判"、"和正 土建尾声 设备进场安装阶段进入"、"看机会原因：资金链断裂"），这些是**权威信息**，必须直接写入对应模块，不要质疑或改写。与简历原文矛盾时**以用户笔记为准**。

### 参考文件的使用原则
- 整体以本 skill 为主要框架，参考文件仅用于修订 skill 中不吻合的细节；**冲突时以参考文件为准修订 skill**
- 参考文件仅用于校准版式样式，不直接套用内容结构
- 分析参考文件格式：Word COM 转 .docx → python-docx 读 bold/size/color/alignment/space_before → zipfile 提取 `word/media/` + PIL 看尺寸，区分标题图（580×48）与装饰图（1180×64 等）

### 格式修改的纪律
- 用户提出任何格式/排版修改时，**主动询问**："这是单次要求还是长期规范？"
- 确认是长期规范 → 保存到 memory + 更新本 skill
- 未明确 → 默认按单次处理，只改当前报告
- 用户讨厌冗余重复，格式更新后只确认"已完成"+关键结果

### 候选人信息时效性检查
用户提供旧报告作参考时**必须主动检查**：最近经历是否仍标"至今"？职业状态是否仍"在职"？公司是否已暴雷/被收购/更名？
- 用户口头补充的新信息**优先于参考文件旧信息**
- 参考文件已严重过时 → 不要直接按过时信息生成，等用户确认
- **跳过确认的情况**：用户主动提供了明确的当前信息（薪资结构、离职原因、到岗时间、家庭情况等），直接使用，无需再问

### 执行文件操作前必须列清单
批量移动/删除/整理文件前，先列出具体操作清单，经用户确认后再执行最后一步。

### 回复纪律
- 不重复已保存的内容；创建/更新后只确认"已完成"+关键结果
- 让用户自己查看 skill 获取完整信息

## 七、反编译对标工作流（格式问题必走）

**触发**：用户说"格式不对""排版不对""和之前不一样"，或生成前就有一份近期真实样本。

**铁律：先反编译，再动手。禁止凭肉眼看图猜属性。**

1. 找一份近期真实样本（用户自己出的报告优先，如 `人选简历\**\锐仕方达-*.docx`）
2. 跑脚本：`python <技能目录>/scripts/docx_reverse_engineer.py <样本.docx>`
3. **必须核对页眉页脚 XML**：
   - 图片在不在页眉：拆 `word/header1.xml` 看 `<w:drawing>`
   - 对齐以 `<w:jc w:val="..."/>` 为准，**不以视觉为准**
   - 图片尺寸看 `<wp:extent cx cy>`，换算 cm = 值 / 360000
4. 生成后**再跑一次同一脚本 + diff**，逐项确认一致才算完

**已验证属性基线（样本：兰雪平-生产副总，2026-10-23）**：见本文档「⓿ 速查铁律」尺寸表，以及：Normal = Times New Roman + eastAsia 宋体 / 10.5pt / 行距1.5 / 段前段后0；基本信息表 Normal Table 样式列宽 7.63cm；工作经历标题行半角括号紧贴时间；综合评估子模块【标签】与内容同段；编号职责首项与标签同段、后续每项各占一段。

## 八、常见陷阱

### 公司介绍必须搜索补充（强制执行）
必须 50-100 字，**即使参考文件有该字段但为空或只有一句话，也必须搜索补充**。搜索内容：成立时间、总部/上市信息、主营业务、核心产品/客户、规模数据。用平台自带网页搜索工具，关键词=公司完整名称。

**降级策略**：搜索不可用、返回空、或返回**完全不相关**的结果（如搜小微型私企返回别的上市公司年报）时，等同于搜索失败，不要用无关结果。改为基于简历原文提炼（公司介绍/工作概述段落 + 行业定位 + 主营 + 核心产品客户）。**底线：即使搜索失败，公司介绍也要达到 50 字左右，不可省略。**

### 旧版 .doc 文件读取
python-docx 读不了 .doc。需用 Word COM 转 .docx 后再分析。⚠️ 同一 COM 会话连续转换多个 .doc 时，第 2 个起容易报 RPC 错误（0x800706BE / 0x800706BA）——**每个文件用独立 COM 会话**（新建 → 转换 → Quit）；仍失败先杀进程等 3 秒重试；始终不行就告知用户请其提供 PDF/DOCX。

### WPS COM 读取只读位置的 .doc
本机无 MS Office 时 Word COM 实连 WPS，只读位置（如同步目录）的 .doc 会报 3010，**先复制到可写目录再调 `KWPS.Application`**。

### 标题图片容易漏
- 脚本复制到工作目录后 `assets/` 找不到 → 页眉 logo、顶部标题图、模块标题图**全部缺失**（退化成蓝色文字/【】文字/直接没有），用户会反馈"页面布局不正确"。**ASSETS 必须指向技能 assets 的绝对路径**，或用环境变量/配置项传入
- 顶部"简历报告"标题图只定义了变量却没写插入段落的代码 → 正文直接从"推荐职位"开始，没有封面大标题
- 自检：生成后导 PDF 渲染首屏，确认页眉有 RISFOND logo、正文首行有居中标题图、各模块有标题图

### 保存被 Word/WPS 占用
覆盖已打开的文件报 `PermissionError: [Errno 13]`。处理顺序：
1. 先 `doc.save(out + '.tmp')`，再多轮 `os.replace(tmp, out)` 重试（间隔 1.5s）
2. 仍失败 → 结束 Word/WPS 进程（⚠️ 会关掉用户所有窗口，先确认），sleep 2 秒
3. 再失败 → 降级存为 `xxx_new.docx` 并说明
4. ⚠️ 顺带清理 `~$` 开头的 Office 锁文件，它也会导致替换失败

### zipfile 提取图片跳过空目录条目
否则 PIL 报 UnidentifiedImageError。

### 简历头部概述与正文口径不一致
候选人简历头部用大字写"管理1000人以上团队""年营收10亿+"，正文却写"直接管理120人核心团队"——**头部放大数字一律不采信，按正文保守口径落笔**，并在汇报时明确告知用户"大数字没敢用"。

### 报告交付时附"待核实字段清单"
生成 docx 后，交付消息里固定附一小节列出本次的待核实项（典型：空白年限、下属人数、汇报对象、到岗周期、看机会原因真实性），并说明哪些是简历原文、哪些是估算补写、哪些按用户指示写。用户拿报告去见客户前能一眼看到哪些是雷。

### 跨平台分享
保持 skill 内容独立完整，不依赖特定平台功能。分发：推 Git 仓库后按各平台机制安装，或把整个目录复制给对方，或把 SKILL.md 当提示词直接用。
